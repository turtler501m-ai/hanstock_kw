# 화면 버튼 기능 및 클릭 로그 목록

API를 실행하는 버튼은 한 번의 동작을 모아 `trader.log`에 한 줄로 기록한다.

`[버튼] ID=... 이름=... 대상=... 결과=성공 API수=2 요약=정상 처리`

HTTP 오류뿐 아니라 응답의 `ok=false` 또는 `status=failed/error/blocked`도 실패로 기록한다. 여러 API를 호출해도 최종 결과 한 줄만 남긴다. API가 없는 탭 이동·닫기·정렬 버튼은 로그에서 제외한다.

### 로그 검토 기준

- `결과=성공`: HTTP와 응답 본문 모두 정상으로 판정됐다.
- `결과=접수`: 백그라운드 실행 또는 승인대기 등록이 정상 접수됐다.
- `결과=실패` 또는 `통신 실패`: HTTP 오류, 업무 실패 상태 또는 브라우저 통신 오류다.
- `API수`: 한 번의 버튼 동작에서 확인한 API 응답 개수다.
- 여러 API 중 하나라도 실패하면 최종 결과는 실패다.

운영 서버에서 최근 버튼 로그만 확인하려면 다음 명령을 사용한다.

```bash
grep '\[버튼\]' logs/trader.log | tail -n 100
```

실패 또는 통신 오류만 확인하려면 다음 명령을 사용한다.

```bash
grep '\[버튼\]' logs/trader.log | grep -E '결과=(실패|통신 실패)'
```

화면에는 클릭 로그용 메시지를 별도로 표시하지 않는다. 동적으로 생성되는 종목·전략·주문 버튼도 같은 방식으로 기록하며, 종목코드나 주문·전략 ID는 `대상`에 남긴다.

정적 HTML 기준 버튼은 국내주식 84개, 미스톡 63개, AI 스톡 9개, 내러티브 16개, 환경설정 4개, FinRL 1개로 총 177개다. 테이블 행에 생성되는 동적 버튼은 개수와 관계없이 이벤트 위임으로 모두 기록한다.

### JavaScript 동적 버튼 유형

- 테이블 정렬, 전략 설정 저장
- 전략 전량매도, 전략 귀속매도, 수동 매수, 승인요청
- 전략 적용, 성과, 자율 실행, 자가진화, 상세, 삭제
- 관심종목 삭제, 후보 이력 삭제, 판단 근거 상세보기
- 미체결 주문 취소, 승인 재처리, 미체결 취소 후 재처리
