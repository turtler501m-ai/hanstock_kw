# 키움 REST 구현 내역

작성일: 2026-08-14

## 구현 완료

- OAuth `au10001` 토큰 발급과 만료 전 갱신
- 운영/모의 도메인 분리
- `authorization`, `api-id`, `cont-yn`, `next-key` 처리
- 모의 TR별 초당 1회, 운영 조회/주문 각각 초당 5회 제한
- `kt00018` 계좌평가잔고와 `kt00001` 예수금 통합
- `ka10001` 현재가
- `ka10081` 국내주식 일봉과 연속조회
- `ka20006` 업종 일봉
- `ka10030` 거래량 순위
- `kt10000` 매수, `kt10001` 매도
- `kt10002` 정정, `kt10003` 취소
- `kt00007` 주문체결내역 및 주문 snapshot 변환
- 기존 대시보드를 위한 KIS-shaped 임시 호환 응답
- 국내주식 broker factory에서 KIS/키움 선택
- 환경설정 화면에서 운영·모의 키움 자격증명 관리
- 환경설정 API의 모든 secret 평문 반환 차단
- 미국주식 `ust21070` 잔고·보유종목 연속조회와 미스톡 호환 변환
- 미국주식 broker 선택 및 시장별 모의계좌 자격증명 분리
- 환경설정 화면의 미국주식 broker와 모의·실전 자격증명 관리

미국주식은 현재 모의계좌 잔고 조회만 지원한다. 주문 adapter와 실전 환경은 아직
구현 완료 범위에 포함하지 않는다.

## 주문 안전 경계

- 기본 broker는 계속 `kis`다.
- `DRY_RUN` 등 기존 실행 정책이 주문을 허용하지 않으면 키움 주문 transport를 호출하지 않는다.
- `KIWOOM_TRADING_ENV`와 `TRADING_ENV`가 다르면 키움 broker 생성을 거부한다.
- 운영/모의 키와 시크릿을 별도 필드로 관리한다.
- 자격증명이 없으면 KIS로 fallback하지 않고 명시적으로 실패한다.
- 모의투자 주문의 기본 거래소는 KRX다.

## 인증 확인 및 실제 계정 검증 제한

- 공식 필드 기반 mock 계약 테스트와 별도로, 등록된 VM 네트워크에서 국내·미국
  모의계좌의 OAuth 토큰 발급이 각각 성공하는 것을 수동 smoke test로 확인했다.
- 이 확인은 App Key/Secret과 허용 네트워크가 유효하다는 범위이며 애플리케이션의
  토큰 캐시, 자동 갱신, 시장별 토큰 격리가 검증되었다는 뜻은 아니다.
- 국내·미국 실제 잔고 조회는 아직 애플리케이션 경로로 검증하지 않았다.
- 국내 모의주문의 매수·정정·취소·체결 동기화는 아직 실제 계좌 검증 전이다.
- 미국주식 잔고 adapter와 미스톡 연동은 구현됐지만 실제 VM 잔고 응답 검증 전이다.
- 미국주식 주문 adapter와 미국 모의주문 생명주기는 구현·검증 전이다.
- 조건검색과 실시간 체결 WebSocket은 후속 단계다.
- NXT/SOR 주문은 모의 KRX 검증 후 별도 활성화해야 한다.
