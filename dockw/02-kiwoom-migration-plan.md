# 키움 REST API 전환 계획

## 1. 기준선 확립

- 복사된 애플리케이션의 import 및 단위 테스트를 실행한다.
- 한스톡, 미스톡, 환경설정 페이지와 핵심 API의 smoke test를 만든다.
- 기존 실패가 있으면 키움 변경 전에 기록하고 분리한다.

완료 조건: 세 화면이 로컬에서 열리고 네트워크 호출 없이 핵심 테스트가 통과한다.

## 2. 증권사 공통 계약 도입

- 잔고, 시세, 일봉, 주문, 정정·취소, 체결내역의 내부 모델을 정의한다.
- `DomesticStockBroker` 인터페이스와 broker factory를 만든다.
- 기존 KIS 구현을 어댑터로 연결하고 KIS 원본 응답 접근을 제거한다.

완료 조건: `DOMESTIC_STOCK_BROKER=kis`에서 기존 결과가 유지된다.

미국주식은 국내주식 계약을 무리하게 재사용하지 않고 거래소 코드, 통화, 주문 및
잔고 필드 차이를 반영한 계약 또는 adapter 경계를 별도로 정의한다.

## 3. 키움 REST 클라이언트 구현

- 운영·모의 도메인과 OAuth 토큰 생명주기를 구현한다.
- 국내·미국 모의계좌의 자격증명, 토큰 캐시와 갱신 경로를 서로 분리한다.
- `api-id`, `cont-yn`, `next-key` 헤더와 연속조회를 공통 처리한다.
- 잔고, 현재가, 일봉, 업종 차트, 순위정보를 내부 모델로 변환한다.
- 운영과 모의 환경에 맞는 호출 제한, 재시도, circuit breaker를 적용한다.

완료 조건: mock 기반 계약 테스트와 애플리케이션 내부에서 국내·미국 모의계좌의
토큰 발급·캐시·자동 갱신 및 잔고 조회 smoke test가 통과한다.

## 4. 주문 생명주기 전환

- 매수·매도, 정정·취소 요청을 키움 주문 형식으로 변환한다.
- KRX를 초기 기본 거래소로 사용하고 NXT/SOR는 별도 검증한다.
- 부분체결, 미체결, 거절, 통신 타임아웃 후 주문조회 흐름을 구현한다.
- 승인, DRY_RUN, 실거래 차단 로직을 broker 호출보다 앞에 유지한다.

완료 조건: 키움 모의계좌에서 주문부터 체결 동기화와 취소까지 재현된다.

국내주식과 미국주식의 주문 생명주기는 각각 검증한다. 국내 모의주문은 KRX를
기본으로 하고, 미국주식은 키움이 요구하는 미국 거래소 코드를 내부 값으로
정규화한다.

## 5. 조건검색 및 WebSocket

- 영웅문4 조건식 목록과 일반·실시간 조건검색을 연결한다.
- 실시간 주문체결 이벤트를 내부 체결 모델로 정규화한다.
- 재접속, 중복 이벤트, 구독 복구를 테스트한다.

완료 조건: 연결 재시작 후에도 체결 중복 없이 주문 상태가 복구된다.

## 6. 대시보드와 설정 정리

- KIS 고정 문구를 현재 선택된 증권사명 또는 해당 시장 계좌로 변경한다.
- 국내·미국 키움 자격증명과 각각의 연결 상태를 환경설정 화면에 추가한다.
- 화면에서 토큰·시크릿을 노출하지 않고 로그에서도 마스킹한다.
- 한스톡·미스톡·환경설정 외 라우트의 제거 가능성을 검증한다.

## 7. 운영 전환

1. `DRY_RUN=true`에서 국내·미국 키움 시세를 각각 비교한다.
2. 국내·미국 모의계좌의 애플리케이션 OAuth, 토큰 갱신과 잔고 조회를 검증한다.
3. 국내 모의계좌에서 주문 전체 흐름을 검증한다.
4. 미국 모의계좌에서 주문 전체 흐름을 검증한다.
5. 안정화 기간에는 KIS 조회와 키움 조회의 차이를 기록한다.
6. 두 시장의 모의투자 검증 완료 후 키움을 기본값으로 바꾸되 KIS 롤백 설정을 유지한다.
7. 실계좌 검증과 실전투자 활성화는 별도 승인과 계획으로 진행한다.

## 주요 위험

- KIS 원본 응답에 대한 화면·전략의 암묵적 의존
- 모의투자와 운영 서버의 지원 거래소 및 호출 제한 차이
- 주문 타임아웃 후 재주문에 따른 중복 체결
- KIS와 키움의 체결·잔고 조회 시점 및 필드 의미 차이
- 국내·미국 계좌 자격증명이나 토큰 캐시가 섞여 잘못된 계좌로 호출될 가능성
- 미국 거래소 코드, 통화, 거래일과 주문 가능 시간의 차이
